## Who it's for

- Write in plain language. No developer jargon on screen, no package names, no evdev codes; those belong only under a "Developer details" disclosure, as in §10.
- Never lorem ipsum. Use the real copy and the real data named below.

## The device being mocked (all measured; §2)
- **Screen:** Xiaomi Pad, landscape **1164 × 777 dp**, 440 dpi.
- **Settings the mock-ups default to:**
  - dark mode;
  - font scale **1.25**, which Android applies **nonlinearly** (see "Font scale");
  - **Bold text on:** every font weight is +300, so 400 renders as 700.
- **Font:** the system font is MiSans. The preview uses **Roboto Flex** (Google Fonts) as a stand-in and says so.
- **Home screen:** app names are hidden. Icons render at 168 px, which is 61 dp, in a superellipse mask (|x|^4.4 + |y|^4.4 = 1).

## House style (§3.2)
- **WiFiBar's sibling:**
  - neutral canvas `#F5F5F7` (light) / `#1C1C1E` (dark);
  - flat tonal cards on `surface-container-*`, with no drop shadows;
  - section labels in `primary`, title size;
  - big numeric readouts;
  - hairline (1 dp) data graphics.
- **Weights:** 400 for body, 500 for titles, never above 600. Emphasis comes from size and colour, because Bold text adds 300.
- **Corners:** xs 8, s 12, m 16, l 24, xl 28, full 999 (dp).
- **Spacing:** a 4 dp grid. Gutters 24, card padding 20, gaps 12 or 16.
- **Touch targets:** at least 48 × 48 dp, always.
- **Icons:** Material Symbols Rounded, as SVGs in `docs/redesign/assets/symbols/<name>.svg` and `<name>_fill.svg`. Filled means selected or active.
- **Never** use Material 3 Expressive-only components (§3.7): button groups, floating toolbars, loading indicators, shape morphing. Use standard M3 shapes (cards, lists, segmented buttons, chips, switches, sheets, a navigation rail) or simple custom equivalents that Compose can draw.

## Token contract
Every colour is a CSS variable named after the Material 3 role, in kebab case:
- **Primary, secondary, tertiary:** `--primary --on-primary --primary-container --on-primary-container --secondary --on-secondary --secondary-container --on-secondary-container --tertiary --on-tertiary --tertiary-container --on-tertiary-container`
- **Error:** `--error --on-error --error-container --on-error-container`
- **Surfaces:** `--background --on-background --surface --on-surface --surface-variant --on-surface-variant --surface-container-lowest --surface-container-low --surface-container --surface-container-high --surface-container-highest --surface-bright --surface-dim`
- **Outlines and the rest:** `--outline --outline-variant --inverse-surface --inverse-on-surface --inverse-primary --scrim`
- **Semantic** (separate from the brand): `--good --warn --bad`.

Values come from `docs/redesign/tokens.css`, generated by `padstudio/design/make_tokens.mjs`. It covers five palettes (Violet, Ocean, Rose, Emerald, Graphite) × light/dark, selected by `data-palette` and `data-theme` on the mock frame.

Type roles: `--t-display`, `--t-headline`, `--t-title`, `--t-body`, `--t-label`, each with `-size` and `-line` in px, where 1 dp = 1 px inside the frame.

| Role | Size / line (sp) |
|---|---|
| display | 36 / 44 |
| headline | 28 / 36 |
| title | 20 / 28 |
| body | 16 / 24 |
| label | 13 / 18 |

Weight variables: `--w-regular: 400`, `--w-medium: 500`, `--w-semibold: 600`. `docs/redesign/fontscale.js` rewrites the sizes for the chosen scale, and `[data-bold="on"]` adds 300 to the weights.

## Font scale
`fontscale.js` holds Android's real lookup tables, copied from AOSP `FontScaleConverterFactory.java` (GitHub mirror `aosp-mirror/platform_frameworks_base`, commit `64130047`):

| Scale | Converted sizes |
|---|---|
| (from, sp) | 8, 10, 12, 14, 18, 20, 24, 30, 100 |
| 1.2 | 9.6, 12, 14.4, 17.2, 20.4, 22.4, 25.6, 30, 100 |
| 1.3 | 10.4, 13, 15.6, 18.8, 21.6, 23.6, 26.4, 30, 100 |
| 2.0 | 16, 20, 24, 26, 30, 34, 36, 38, 100 |

The script uses the full set of keys, and interpolates linearly between tables and between table points, as Android does. Line heights scale by the same ratio as their size.

**Fragment format:**
- One `<section class="mock" data-screen="<screen>">` containing the 1164 × 777 frame.
- Your own classes are prefixed `m-<screen>-`.
- Shared components come from `kit.css` classes. No inline `<script>` except tiny, guarded progressive enhancement.

## Real content to use
- **Pen:**
  - Focus Pen Pro, Expert setup, controls squeeze / slide up / slide down / double tap.
  - Contexts and default actions come from `padstudio/core/src/main/kotlin/com/charan/padstudio/core/pen/DefaultProfiles.kt`; the action list from `PenModel.kt:89-115`.
  - The UI relabels in plain language, but never renames core labels in code (§4).
- **Status copy:** follows §7 exactly. Never "verified", never "Expert running". For example "Sent to Key Mapper 14:05", "Key Mapper is listening", "Pen actions on (as last requested)", "Can't be checked from the tablet".
- **Home groups:** the names in `padstudio/core/src/main/kotlin/com/charan/padstudio/core/home/AppGroup.kt`.
- **App icons and names:** only those in `assets/manifest.json`, which come from the user's own home-screen screenshots.
- **Home-screen grid (§6):** the Home Kit mock-up shows **both** possible outcomes of the HyperOS check:
  - **G5-A:** HyperOS layout options drawn as small previews, plus a "Recorded … : 6 × 5" baseline and "Change in HyperOS".
  - **G5-B:** "HyperOS on this tablet has no grid setting", with the nearest options.

  A `data-g5` attribute switches between them; the assembler sets the measured one, or shows both labelled "measuring when the tablet is unlocked".
- **Widget grid (§6b):** Auto, 6×3, 8×4, 10×5 and custom (columns 4–10, rows 2–8). Fit rule: cells ≥ 48 dp; usable width = widget − 20; usable height = widget − 20 − 28 header; "+N" in the last cell. Show a refused grid with its reason, and a trimmed widget with its header note.
